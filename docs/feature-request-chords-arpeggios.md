# FretNote 三音和弦与琶音练习开发需求

状态：学习模式已实现；新增和弦／琶音音频练习仍为需求草案。更新日期：2026-10-08。

本功能提供无需输入的学习模式，以及需要演奏的练习模式。学习模式直接展示指板；练习模式区分和弦 Chord 与琶音 Arpeggio。学习和练习共享两类材料：135 三和弦与 137 七和弦骨架，每项只包含三个不同的和弦音。用户通过和弦名称、音级与根音所在弦理解题目，无须记忆转位术语。

乐理说明、参考路径和 135 品位表见 [练习资料](triad-practice.md)。本文件定义开发范围、判定行为和验收要求；待定事项不应被当作已批准需求。

## 1 目标与现状

用户希望把指板音名练习推进到三个音之间的关系：既能按出和弦，也能依次弹出琶音，并得到可靠反馈。

当前 App 已有单音音高检测、音名找音、五线谱找音、短旋律、指板提示和本地学习记录。单音检测不能直接判断同时发声的和弦。已有练习继续保留，不因新增模式改变原有答题规则。

成功标准是：题目表达明确、生成位置可弹、反馈符合演奏方式、记录能区分不同练习。音频只能验证声音，不声称验证物理弦位或左手指法。

## 2 确认的功能范围

| 维度 | 范围 |
| --- | --- |
| 使用方式 | 学习：直接看指板，无需输入；练习：演奏后判定 |
| 演奏模式 | Chord：三音一起响；Arpeggio：三音依次弹 |
| 135 类别 | Major、Minor、Augmented、Diminished |
| 137 类别 | Major 7、Dominant 7、Minor 7 |
| 调弦与品位 | 标准调弦 E2 A2 D3 G3 B3 E4；不超过 21 品 |
| 题目语言 | 和弦名＋音级排列或演奏顺序＋根音所在弦 |
| 运行方式 | 仅 macOS 本地，声卡或麦克风输入，音频不录制、不上传 |
| 视觉风格 | 延续黑白、深浅色、可调字号和不需要上下滚动的布局 |

每题只使用三个不同的和弦音。137 省略五音，不扩展为完整四音七和弦。小大七、减七骨架、sus、扩展音、自由和弦识别、节奏评分均不在本次范围。

### 和弦构成

| 材料 | 类别 | 目标音级 | 相对根音半音数 |
| --- | --- | --- | --- |
| 135 | Major | 1、3、5 | 0、4、7 |
| 135 | Minor | 1、♭3、5 | 0、3、7 |
| 135 | Augmented | 1、3、♯5 | 0、4、8 |
| 135 | Diminished | 1、♭3、♭5 | 0、3、6 |
| 137 | Major 7 | 1、3、7 | 0、4、11 |
| 137 | Dominant 7 | 1、3、♭7 | 0、4、10 |
| 137 | Minor 7 | 1、♭3、♭7 | 0、3、10 |

Major 7、Dominant 7、Minor 7 的题目分别写作 Amaj7、A7、Am7 等明确名称，不用含糊的“A Major 137”。音名拼写保留和声角色，如 A 增三使用 E♯。

## 3 学习与练习流程

### 学习模式

用户直接查看 fretboard，不需要连接吉他、弹奏、回答问题或提供任何音频输入。进入后直接显示一张完整有效的指型，不能先进入等待输入或答题状态。

- 默认显示三个位置及对应音级、根音所在弦、实际品位，并显示和弦名称与正确音名。
- 学习 Chord 时展示同一组可同时按下的位置；学习 Arpeggio 时展示依次弹奏的路径及顺序。同一弦上的多个位置同时画出，但不暗示这些位置需要同时按住。
- 支持查看已确认范围内的 135 与 137 材料；不因增加学习模式扩展和弦类别或排列。
- 可用选择项或上一项、下一项主动浏览；这些只是导航，不是答题。停留查看不要求任何操作，不自动倒计时或翻页。
- 不隐藏答案，不需要点击“提示位置”，不要求按“开始练习”才能看到指板。
- 不启动音频采集，不申请麦克风权限，不要求选择输入设备；即使拒绝权限或没有音频设备，也能使用完整学习模式。从正在监听的练习切入学习时停止采集，返回练习后由用户显式开启。
- 不显示等待弹奏、正确、错误、得分或答题进度，不把浏览计作练习完成、提示、跳过或熟练度变化。
- 第一版不要求学习打卡、浏览时长统计或声音播放。核心是静态、清楚、可浏览的指板展示。

学习模式可先独立交付，不依赖和弦多音识别完成；也不能把它作为 Chord 判定功能已完成的替代。

### 练习模式


1. 选择 Chord 或 Arpeggio，再选择 135 或 137 材料及练习类别。
2. 按模式选择有效的根音、弦组或根音弦、位置条件。具体控件和默认值属于实现设计，不新增其他和弦类别。
3. 系统先生成完整有效题目，再开始监听判定；条件无解时提示调整，不生成空题或越界答案。
4. 展示和弦名、音级信息、根音所在弦及足以明确目标音区的条件。
5. 用户演奏，得到正确、需重试或未听清的反馈；可以查看提示、跳过和结束。
6. 保存已完成题目与练习记录，不因提前结束丢失成绩。

提示展示参考答案；未提示时不能把要求用户寻找的全部位置直接揭示。若多个八度均可能符合题干，必须明确练习范围或接受哪些位置，不能用隐藏目标拒绝可见条件下的正确答案。

## 4 Chord 功能要求

### 135 和弦

- 仅用 654、543、432、321 四组相邻弦，每弦一个音。
- 使用根–三–五、三–五–根、五–根–三三种密集排列，根据类别显示升降变化。
- 音级排列按实际音高由低到高阅读，不表示扫弦方向。
- 不加入 1–5–3 等开放排列。
- 根音弦必须与弦组和排列一致，不能将三个筛选条件任意拼接。

题目示例：**A Major · 3–5–1 · 根音在第 2 弦**。

若目标范围为 9–12 品，参考答案为 432 弦的 `11 / 9 / 10`，实际音高 C♯4、E4、A4。三个音一起发声才属于和弦练习。

### 137 和弦

初始材料为根–三–七，三音、七音随类别变化。其他排列与跨弦组合见待定项，不自动纳入。

题目示例：**Amaj7 · 1–3–7 · 根音在第 5 弦**。

目标范围为 11–14 品时，一个参考答案为 543 弦的 `12 / 11 / 13`，实际音高 A3、C♯4、G♯4。不能把 135 的品位直接复用为 137。

### 声音判定

- 使用多音分析，验证三个目标音共同存在及其实际音高关系。
- 接受同时拨弦与短时间内扫过三根弦；扫弦容差须用真实输入确定。
- 不通过累计三个互不重叠的单音来宣告和弦正确。
- 不能只比较十二音级集合，必须区分不同低音与八度排列。
- 目标音证据不足或输入模糊时显示“未听清”，不立即判错。清晰的错误组合应要求重试。
- 缺少目标音不能通过；检测到有可靠证据的额外非目标音不能通过。弱噪声与泛音不能直接当成额外音符。
- 一次持续和弦只提交一次结果；下一题须有新的演奏事件，避免延音误答。
- 只在有依据时说明具体缺音或错音；不输出“某根弦没按好”等无法验证的诊断。

## 5 Arpeggio 功能要求

- 三个音依次弹奏，允许同一根弦上有两个目标音。
- 初始顺序为根音出发的上行：135 为 1→三音→五音，137 为 1→三音→七音。
- 食指型、中指型、小指型仅是参考路径名称；实际手指分配不作为答题标准。
- 路径须按调弦计算，正确处理 G–B 弦边界，不能机械平移所有指型。

题目示例：**A7 · 根音在第 5 弦 · 上行 1→3→♭7**。

声音判定要求：

- 逐音检查实际音高、八度和顺序，三个目标事件完成后才记作完成一题。
- 弹错时保留已完成进度，等待当前目标；该题不再计为首次正确。
- 持续音不重复推进，模糊信号不计错。重拨同音与题目切换使用明确的起音门控。
- 验证前音残留对识别的影响；在单音检测适用范围内给出清晰的拨弦与止音说明，不承诺任意叠音可识别。
- 同音高的多条路径均无法由声音区分。反馈表述为音高与顺序正确，不表述为手指或物理弦位正确。

下行、往返及首批路径集合尚未定案。

## 6 指板与谱面

- Chord 提示同时标三个位置；Arpeggio 提示路径顺序和当前目标音。
- 音级标签使用 1、3、♭3、5、♭5、♯5、7、♭7，与手指编号明确区分。
- 五线谱继续使用吉他高八度记谱规则，判题以实际音高为准。
- 保持谱面与指板比例，不能随窗口拉伸变形；文字遵循已有字号设置。
- 最小 1040×740 窗口、100%–175% 字号、深浅色下，核心操作与题目可见，不新增页面纵向滚动。
- 不因标准四品范围删掉所有五品跨度指型而不作说明；跨度策略须落实待定决策后统一应用。

## 7 统计与持久化

以下计分与成绩保存仅适用于练习模式；学习模式浏览不写入答题统计，也不改变复习权重。

新增演奏练习以一个完整三音练习为一题。Chord 一次有效和弦完成一题；Arpeggio 三个目标事件完成一题。不能把三音琶音的三个成功音与一次和弦当成相同数量的完整题目。

建议记录：模式、135/137 材料、类别、根音、音级排列或顺序、要求的根音弦及位置、参考路径、完成时间、首次正确、提示与跳过。根音弦和路径描述题目要求，不代表系统确认了实际演奏动作。

首次正确要求未出现明确错误、未使用提示、未跳过。跳过作为待复习记录，不计正确；提示与跳过分开统计。未完成题目的计数方式与每组题数见待定项。

- Chord 与 Arpeggio 分开统计，135 与 137 分开统计。
- 不把旧单音记录转换成新三音练习成绩。
- 保存已完成题目；重复结束不重复记录；空组不产生历史。
- 升级保留已有学习记录；读取失败时保留原文件，不静默覆盖。

## 8 技术交付建议

以下是实现分工建议，不限定最终代码结构：

| 模块 | 工作 |
| --- | --- |
| FretNoteCore | 和弦构成、音名拼写、排列与位置生成、模式独立的判定状态 |
| 音频分析 | 保留单音链路供琶音使用；增加并验证多音分析，不能将 YIN 单结果当作和弦检测 |
| PracticeStore | 管理三音题目、练习进度、提示、跳过与结束事件 |
| StaffView 与指板 | 显示三个音或顺序路径，沿用比例布局；学习模式始终显示完整位置 |
| 模式切换 | 学习模式与音频采集、判题和成绩写入解耦，独立于设备权限运行 |
| LearningRecord | 新模式与材料分类、兼容旧数据的持久化 |

分析工作继续在主线程之外执行，不上传或保存用户实时音频。算法、阈值和分析窗口通过验证选择，本需求不预设未经测试的准确率或延迟承诺。

可先交付数据规则与无需输入的学习模式，再交付琶音练习、推进和弦多音判定；分阶段不等于用逐音练习替代 Chord。没有达到和弦验收要求时，应明确该模式未完成。

运行 `swift test` 验证题目、判定与持久化；音频测试使用打包后的 App。新增检测测试至少涵盖合成多音、不同强度、泛音、扫弦、缺音、错音与静音，并用真实吉他干净音色输入验证。

发布多音判定前，需记录真实验证的设备、类别覆盖、样本数、误通过率、误拒绝率和判定延迟；具体达标阈值须在算法验证阶段明确，不能只以“合成测试通过”宣告和弦识别可靠。测试不修改用户真实学习数据，音频样本须有使用授权。

## 10 尚需定案的产品决策

| 决策 | 当前边界 |
| --- | --- |
| 空弦 | 尚未决定两种模式是否纳入；不擅自默认全部禁用或全部开放 |
| 把位跨度 | 四品之外的五品指型是扩展显示还是过滤，需要统一规则 |
| 多个八度答案 | 用可见范围限定，或接受明确的一组合法答案；不能隐藏限制 |
| 琶音路径 | 首批具体路径集合、下行与往返是否首期支持尚未确定 |
| 137 排列与弦组 | 已确认根–三–七材料；是否增加其他排列及跨弦按法尚未确定 |
| 每组长度 | 完整三音题为计数单位，但默认每组几题尚未确定，不直接套用旧版“20 音” |
| 琶音中途结束 | 已完成题目必须保留；未完成题目的部分进度是否恢复尚未确定 |

这些事项不妨碍先验证音程与指板规则，但在依赖它们的交互、出题和验收完成前必须定案。新增音频练习尚未交付。


## 11 学习模式首版实现

学习入口为侧栏「指板学习」及 `⇧⌘L`。支持全部十二个根音、135 四类与 137 三类，直接显示音级、音名、根音所在弦及品位。135 和弦显示三种密集排列，137 仅显示根–三–七；琶音展示前两音同弦、后两音同弦、每弦一个音三种参考路径。无合法位置时解释原因，不生成越界图示。

学习页面允许选择是否包含空弦（默认关闭），按完整指型自动适配品位跨度，并提供不同八度位置浏览。以上仅为无需判定的学习浏览行为，不代替演奏练习的空弦、跨度与多答案策略。进入学习停止采集，禁用学习期间的音频启动及练习开始；浏览不写入练习成绩。新增演奏模式尚未实现。
